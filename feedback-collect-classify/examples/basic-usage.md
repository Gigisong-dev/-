# 基本使用示例

## 示例 1：默认配置收集昨日反馈

### 用户请求
```
请收集"本地版答疑群"昨天的用户反馈，写入我们的反馈表
```

### 执行流程
1. **配置确认**
   - 目标表格：使用默认配置或询问用户提供
   - 目标群聊：本地版答疑群
   - 时间窗口：昨天 00:00 ~ 23:59

2. **消息拉取**
   - 搜索群聊：`lark-cli im +chat-search --query "本地版答疑群"`
   - 拉取消息：按时间窗口获取消息列表

3. **数据处理**
   - 筛选有效反馈
   - 生成标准化标题
   - 进行四大分类（默认：技术问题/产品建议/使用咨询/待划定）
   - 补充上下文

4. **结果写入**
   - 写入多维表格
   - 输出统计结果

### 预期输出
```json
{
  "config_summary": {
    "base_token": "bascnxxxxxx",
```

## 示例 3：使用群链接

### 用户请求
```
请收集这个群聊的反馈：https://example.feishu.cn/im/chat/xxxxxxxx
```

### 执行流程
1. **配置确认**
   - 从群链接提取 chat_id
   - 直接使用 chat_id 拉取消息
   - 使用默认时间窗口（前一天）

2. **消息拉取**
   - 直接使用 chat_id 拉取消息
   - 无需搜索步骤

### 优势
- 更快速，无需搜索步骤
- 适用于已知群链接的场景
- 避免群名搜索的歧义

## 示例 4：周一执行（特殊调度规则）

### 用户请求
```
请收集上周五的用户反馈（今天是周一）
```

### 执行流程
1. **时间窗口计算**
   - 当前日期：2026-08-19（周一）
   - 目标日期：2026-08-15（周五，最近一个工作日）
   - 时间窗口：2026-08-15 00:00 ~ 23:59

2. **消息拉取**
   - 拉取周五的消息
   - 补充周四下午的上下文（如需要）

### 调度规则说明
- 周一拉取上周五数据
- 避免周末的数据干扰
- 保持工作日数据的连续性

## 示例 5：周末执行提示

### 用户请求
```
请收集昨天的用户反馈（今天是周六）
```

### 执行结果
```
抱歉，用户反馈收集流程仅在周一至周五执行。
今天是周六，跳过本次运行。
如需收集周末的反馈，请在周一指定具体的时间范围。
```

### 设计考虑
- 周末通常反馈量较少
- 避免无效的周末执行
- 保持工作日的处理节奏

## 示例 7：上下文补全

### 用户请求
```
请收集反馈，注意处理依赖前文的短消息
```

### 场景示例

**原始消息序列：**
1. 用户A: "我昨天更新了系统，今天打开就报错了"
2. 用户B: "报什么错？"
3. 用户A: "错误代码是 0x80070057"
4. 用户C: "还是不行"

### 处理结果

**消息4（"还是不行"）的处理：**
- **原始内容**: "还是不行"
- **上下文补全**: 向前查看消息1-3，找到用户A的完整问题描述
- **context_summary**: "用户A反馈更新系统后出现错误代码0x80070057，用户C表示同样问题仍未解决"
- **standard_title**: "系统更新后出现错误代码0x80070057"
- **问题分类**: "技术问题"
- **置信度**: 85

## 示例 9：置信度评估

### 用户请求
```
请收集反馈，关注低置信度的项目
```

### 场景示例

**反馈1（高置信度）：**
- 反馈原文: "点击保存按钮后没有反应，也没有提示信息"
- standard_title: "点击保存按钮无响应且无提示"
- 问题分类: "技术问题"
- 置信度: 95

**反馈2（中等置信度）：**
- 反馈原文: "这个功能不太好用"
- context_summary: "用户在讨论导出功能时表示不太好用"
- standard_title: "导出功能使用体验不佳"
- 问题分类: "待划定"
- 置信度: 65

**反馈3（低置信度）：**
- 反馈原文: "有问题"
- context_summary: "无法补足上下文，信息严重不足"
- standard_title: "未知问题"
- 问题分类: "待划定"
- 置信度: 45

### 处理策略
- 置信度 ≥ 70: 按分类结果处理
- 置信度 < 70: 统一归为"待划定"，建议人工复核
